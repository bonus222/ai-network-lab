# W12 · IP 信誉与平台风控：为什么「通了」不等于「能用」

> **阶段四 · 风控层** ｜ 预计 6–8 小时 ｜ 前置：[W11](w11-routing-dns.md)
>
> [← W11](w11-routing-dns.md) ｜ [W13 →](w13-quality-eval.md)

## 为什么学这个

到这里你已经能稳定连出去了。然后你会遇到一个新问题：**网页能开，但服务不让你用。**

- 提示「所在地区不支持」
- 要求手机验证
- 登录后被秒封
- 人机验证无限循环

这**不是网络问题，是风控问题**。这一周讲的是：平台在给你的连接打什么分。

> ⚠️ 先读 [`docs/03-compliance.md`](../docs/03-compliance.md)。用代理访问在部分地区不提供服务的平台，通常违反其服务条款，可能导致账号被封。本周的目的是**理解与诊断**，不是教你绕过风控。

## 核心概念

### 1. 平台看到的信号（不止 IP）

| 类别 | 信号 | 说明 |
|:--|:--|:--|
| **网络层** | ASN 类型 | 机房 / 住宅 / 移动 / 企业 |
| | IP 滥用历史 | 是否在公开黑名单、是否被大量账号共用 |
| | 地理一致性 | IP 归属地 vs 时区 vs 语言 vs 支付方式 |
| | 连接质量 | 异常高的延迟、丢包，可能是隧道特征 |
| **协议层** | TLS 指纹（JA3/JA4） | 是不是真实浏览器 |
| | HTTP/2 行为 | 头部顺序、优先级、SETTINGS 参数 |
| **应用层** | 浏览器指纹 | Canvas、WebGL、字体、屏幕、时区 |
| | 账号行为 | 注册时间、登录频率、操作节奏 |
| | 支付信息 | 卡 BIN 的国家 |

**关键认知**：这些信号是**叠加**的。单项可疑不一定拦你，但「机房 IP + 非浏览器 TLS 指纹 + 时区与 IP 不符 + 新账号」四件套凑齐，基本必拦。

### 2. ASN 类型：最粗的那把筛子

| 类型 | 例子 | 平台态度 |
|:--|:--|:--|
| **机房（Datacenter）** | AWS、DO、Vultr、Oracle | 默认低信任。大量爬虫与滥用来自这里 |
| **住宅（Residential）** | Comcast、AT&T、各地 ISP | 默认高信任。真实用户就在这 |
| **移动（Mobile）** | 各大运营商 4G/5G | 高信任，但 IP 共享度极高 |
| **企业（Business）** | 公司专线 | 中等 |

**为什么住宅 IP 也不是万能**：

- 住宅代理池通常由「被感染的设备」或「自愿共享带宽的用户」构成，**同一个 IP 背后可能有几十个人**，滥用历史照样脏
- 住宅 IP 的**地理位置经常不准**（运营商 IP 库更新滞后）
- 住宅 IP 的**延迟和稳定性**通常比机房差
- 大规模使用住宅代理本身就是风控信号（一个「美国家庭 IP」每天登录 50 个账号，正常吗？）

### 3. 地理一致性：最容易被忽略的自伤

平台会交叉验证：

```
IP 归属地 = 美国
浏览器时区 = Asia/Shanghai      ← 不一致
系统语言 = zh-CN                ← 不一致
Accept-Language = zh-CN,zh      ← 不一致
支付卡国家 = 中国                ← 不一致
```

任何一项不一致都会加分（风险分）。**很多人以为自己 IP 干净，其实是被时区卖了。**

### 4. TLS 指纹：代理的天然破绽

这是最讽刺的一点：**你为了抗审查用的协议，可能正是平台识别你的依据。**

- 浏览器（Chrome/Firefox）：JA3/JA4 是公开且稳定的
- Go 的默认 TLS 栈（很多代理客户端用）：指纹与浏览器**显著不同**
- 一些代理客户端会做 uTLS 伪装，但版本滞后于浏览器更新

检测方法：访问 [tlsfingerprint.io](https://tlsfingerprint.io)，看它认为你是什么客户端。

### 5. 一个诚实的结论

> 你无法「完全」伪装成一个本地用户，因为**本地用户不上代理**。
>
> 你能做的是：**减少不一致性**。IP、时区、语言、DNS、指纹，尽量指向同一个「人设」。
>
> 但这不是「绕过风控」的保证书——平台的风控是持续演进的，而且它的目标本来就不是「让你用」。

## 实验：给自己做一次「体检」

```bash
# 1. 出口信息
curl -s https://ipinfo.io/json

# 2. 滥用评分（网页版更直观）
#    https://scamalytics.com/ip/<你的IP>

# 3. 本地时区
#    Windows:  Get-TimeZone
#    macOS:    sudo systemsetup -gettimezone

# 4. 浏览器指纹
#    https://tlsfingerprint.io
#    https://browserleaks.com/canvas
```

把四项结果并排看，问自己：**如果我是风控系统，这个组合像什么？**

## 自测

1. 机房 IP 和住宅 IP 在风控眼里差在哪？为什么住宅 IP 也不保证可用？
2. 「地理一致性」包括哪几个维度？为什么时区是重灾区？
3. TLS 指纹为什么会成为代理的破绽？uTLS 能完全解决吗？
4. 为什么「同一 IP 登录大量账号」本身就是风险信号？
5. 平台的地区限制，本质上是技术问题还是商业/合规问题？
