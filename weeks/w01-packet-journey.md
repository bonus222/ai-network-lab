## 为什么先学这个

所有「绕过检测」的技术，本质都是在**改变数据包长什么样**。如果你不知道正常的数据包长什么样，就不可能知道该改哪里。

这一周不碰任何代理软件。只做一件事：把「你敲下回车到页面出现」这一秒钟里发生的事，拆到能逐包解释。

## 核心概念

### 1. 分层与封装

TCP/IP 四层，从上到下每一层给数据加一个「头」：

| 层 | 单位 | 关键字段 | 你会在抓包里看到 |
|:--|:--|:--|:--|
| 应用层 | 消息 | HTTP 请求行、TLS 记录 | `HTTP`, `TLS` |
| 传输层 | 段 / 数据报 | 源端口、目的端口、序号、标志位 | `TCP`, `UDP` |
| 网络层 | 包 | 源 IP、目的 IP、TTL | `IPv4`, `IPv6` |
| 链路层 | 帧 | MAC 地址 | `Ethernet` |

关键点：**每一层只关心自己的头**。中间路由器只看 IP 头，看不到你的 HTTP 内容——这就是为什么「加密」能起作用，也是为什么「元数据」（谁在什么时候连了谁）永远藏不住。

### 2. IP、端口、NAT

- IP 负责「送到哪台机器」，端口负责「交给哪个程序」
- 你家的路由器做了 NAT：内网 `192.168.x.x` 被换成公网 IP + 一个随机端口
- 所以从外面看，你全家所有设备都来自**同一个公网 IP**——这个事实在 W12 会变得非常重要

### 3. TCP 与 UDP

| | TCP | UDP |
|:--|:--|:--|
| 连接 | 三次握手建立 | 无连接，直接发 |
| 可靠性 | 重传、保序 | 不保证 |
| 开销 | 大 | 小 |
| 典型用途 | HTTP/1.1、HTTP/2、TLS | DNS、QUIC（HTTP/3）、游戏、视频 |

三次握手：`SYN →` `← SYN+ACK` `ACK →`。为什么不是两次？因为要让**双方都确认**对方的收发能力正常。

### 4. MTU 与 MSS

- MTU（最大传输单元）以太网默认 **1500 字节**
- MSS = MTU − IP 头(20) − TCP 头(20) = **1460**
- 超过 MTU 的包会被分片，分片会拖慢速度、也更容易被中间盒干扰

### 5. DNS：把名字换成地址

- 查询链路：浏览器缓存 → 系统缓存 → 你的 DNS 服务器（递归解析）→ 根 → 顶级域 → 权威服务器
- 记录类型：`A`(IPv4) / `AAAA`(IPv6) / `CNAME`(别名) / `TXT` / `HTTPS`(含 ECH 公钥)
- 默认走 **UDP 53**，响应超过 512 字节或做区域传送时改走 TCP
- `DoH`（DNS over HTTPS）/ `DoT`（DNS over TLS）把查询也加密了

**为什么重要**：DNS 查询是明文 UDP，审查方可以直接伪造响应（DNS 污染）。这是最古老也最省力的封锁手段。

## 实验：让抓包自己说话

打开 Wireshark 后按这个顺序观察，每一步都问自己「这个包在解决什么问题」：

1. **DNS 查询**：过滤器 `dns`。看 query 和 response 的 IP 是否一致、TTL 是多少。
2. **TCP 握手**：过滤器 `tcp.port == 443`。找到 `SYN`、`SYN, ACK`、`ACK` 三个包，看序号（Seq/Ack）如何互相确认。
3. **TLS 握手**：过滤器 `tls`。找到 `Client Hello`，展开看 `Random`、`Cipher Suites`、`Extensions`。
4. **数据传输**：看包长分布。你会发现大部分包接近 1460 或 1448——这是 MSS 在起作用。

> 记录一个反直觉的发现：**加密之后，包长和时序仍然暴露了大量信息**。这是后面所有「流量指纹」技术的基础。
