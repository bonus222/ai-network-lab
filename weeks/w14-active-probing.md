## 为什么学这个

被动观察只能看流量。要确认「这是不是代理」，最可靠的办法是**主动去连它**。

这一周你要站到审查方那一侧：**如果我是探测者，我会怎么试？** 只有想清楚这个，才能理解 REALITY 和回落机制为什么那样设计。

## 核心概念

### 1. 主动探测的历史

2015 年的论文《Examining How the Great Firewall Discovers Hidden Circumvention Servers》系统描述了这套机制：

1. 被动流量里发现**可疑的 IP:端口**（比如非标准端口上的长连接、异常包长分布）
2. 对该地址发起**主动连接**
3. 用多种「探针」测试，观察响应
4. 判定为代理 → 封锁 IP

关键洞察：**审查方不需要破解加密，它只需要让服务器「自己承认」。**

### 2. 探针的种类

| 探针 | 目的 | 服务器若「正常响应」意味着 |
|:--|:--|:--|
| **标准 TLS 握手** | 看是不是 Web 服务器 | 是 Web 服务器（安全） |
| **重放旧包** | 看是否接受重复会话 | 无状态协议会中招 |
| **残缺握手** | 看错误处理 | 返回协议特定错误 = 暴露 |
| **随机字节** | 看是否崩溃/断开 | 直接断开 = 可疑 |
| **协议变体** | 试不同版本的握手 | 版本特定响应 = 暴露 |
| **端口扫描** | 看还开了什么 | 开了奇怪端口 = 可疑 |
| **时序探测** | 看响应延迟 | 固定延迟 = 机器行为 |

### 3. 探测抵抗的四种策略

| 策略 | 做法 | 代表 |
|:--|:--|:--|
| **回落** | 认证失败就转发给真实网站 | Trojan |
| **无响应** | 对任何非法连接直接超时 | 部分自研协议 |
| **借壳** | 让探测者连到的就是真网站 | REALITY |
| **认证前置** | 认证不过就不给任何协议响应 | REALITY / SS-2022 |

**「无响应」的代价**：正常用户如果配置错了，也得不到任何错误提示，排错地狱。而且「一个 IP 上 443 端口完全无响应」本身就可疑（正常网站不会这样）。

所以实践中 **「借壳」优于「回落」优于「无响应」优于「返回错误」**。

### 4. REALITY 的设计取舍

REALITY 选择了最激进的方案：**对未认证连接，我不做任何判断，直接当 TCP 转发。**

- 优点：探测者拿到的**永远是真实网站的响应**，零信息泄露
- 代价：需要一条到真实站点的稳定连接；`dest` 选不好会拖慢速度；无法对恶意扫描做限速（因为看起来就是正常访问）

> 这是一个典型的工程权衡：**把「不可区分性」做到极致，代价是「可观测性」和「效率」。**

### 5. 一个思维练习

假设你要设计一个「探测抵抗评分」，你会考察哪几个维度？

参考维度：
- 未认证连接的响应是否与真实网站**逐字节一致**
- 重放是否被接受
- 错误输入的处理是否暴露协议特征
- 响应时序是否有人为特征
- 端口开放面是否最小

## 实验：自己当一次探测者

```python
import socket, time, ssl

def probe(host, port, payload=b"", timeout=3):
    t0 = time.time()
    try:
        s = socket.create_connection((host, port), timeout=timeout)
        if payload:
            s.sendall(payload)
        data = s.recv(1024)
        s.close()
        return {"elapsed": round(time.time()-t0, 3),
                "got_bytes": len(data),
                "first": data[:16].hex()}
    except Exception as e:
        return {"elapsed": round(time.time()-t0, 3), "error": type(e).__name__}
```

对同一端口跑四种输入，比较 `elapsed` 和 `got_bytes`。

> 判据：如果「随机字节」和「正常握手」的响应**几乎一样**，说明服务端没有根据输入做区分——这正是 REALITY 想要的效果。
