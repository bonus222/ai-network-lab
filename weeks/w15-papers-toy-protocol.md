## 为什么学这个

到这里，你用的都是别人设计的协议。这一周你要**自己设计一个**——哪怕它很玩具。

目的不是造一个能用的工具，而是：**当你亲手试过「把包长分布改掉」之后，你会真正理解它有多难、代价有多大。**

## 核心概念

### 1. 论文怎么读（五问法）

读任何一篇系统/安全论文，只回答五个问题：

1. **问题**：它要解决什么？（一句话）
2. **威胁模型**：假设对手能做什么、不能做什么？
3. **方法**：核心机制是什么？（画一张图）
4. **评估**：怎么证明有效？数据集、指标、基线是什么？
5. **局限**：作者自己承认的、以及没说的弱点是什么？

> 读不懂公式没关系，**跳过公式先看图和结论**。80% 的价值在图 1 和最后一节。

### 3. 玩具协议设计

目标：让一条 TCP 连接在**包长分布**上看起来更像正常流量。

**问题**：正常应用写入的数据长度是随机的（受内容、缓冲、MSS 影响），而隧道协议往往有固定头部，产生规律性的长度峰值。

**朴素方案**：

```
[2B 长度][载荷]
```

→ 包长 = 载荷长度 + 2，直接暴露载荷长度分布。

**改进方案：定长分桶 + 随机填充**

```
[2B 真实长度][1B 填充长度][载荷][随机填充]
                     ↓
        整帧补齐到 128 / 512 / 1024 / 1400 之一
        （按真实流量的经验分布采样，而不是均匀随机）
```

**再加一层：时序整形**

```python
# 每个包发出前加一个服从指数分布的微小延迟
delay = random.expovariate(1 / 0.002)   # 均值 2ms
time.sleep(min(delay, 0.02))
```

**代价**：

| 手段 | 收益 | 代价 |
|:--|:--|:--|
| 定长分桶 | 消除长度指纹 | 带宽浪费（最多 2 倍） |
| 随机填充 | 打散残余规律 | 同上，且增加 CPU |
| 时序整形 | 消除机器节奏 | **直接增加延迟**，交互体验变差 |

> 这就是所有混淆技术的共同困境：**你花在「像人」上的每一分力气，都要从「快」里扣。**

### 4. 怎么验证「有效」

不能靠感觉。做法：

1. 抓包，导出每个包的 `tcp.len`
2. 画直方图
3. 和「正常 HTTPS 流量」的直方图对比
4. 算一个距离指标（如 **KL 散度** 或 **JS 散度**）

```python
import math
def kl(p, q):
    """p、q 是归一化后的长度分布（dict: 长度 -> 概率）"""
    keys = set(p) | set(q)
    eps = 1e-9
    return sum(p.get(k, eps) * math.log(p.get(k, eps) / q.get(k, eps)) for k in keys)
```

**KL 散度越小，说明两个分布越接近，混淆越成功。**

## 实验：看见「填充」的代价

```
不加填充：  包长集中在 40 / 200 / 1400  →  三个尖峰，异常好认
加填充后：  包长集中在 128 / 512 / 1400  →  峰还在，但位置变了
```

**注意一个反直觉的结论**：定长分桶**没有消除峰值，只是移动了峰值**。真正的正常流量也有峰值（受 MSS 影响）。所以：

> **目标不是「没有峰值」，而是「峰值的形状和正常流量一样」。**
>
> 这是整个抗审查领域最核心的美学：**不是消除特征，而是复制特征。**
