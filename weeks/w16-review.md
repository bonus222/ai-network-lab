## 为什么学这个

学完 15 周，你脑子里有一堆碎片。最后这一周做三件事：

1. **把它们焊成一个整体**（报告）
2. **验证它真的能用**（压测）
3. **把它抽象成可迁移的方法论**（这才是最值钱的部分）

## 核心概念

### 1. 终期报告的结构

不要写成流水账。用这个骨架：

```
1. 问题与范围
   - 我要解决什么？不解决什么？（划清边界）
2. 威胁模型
   - 对手是谁？能做什么？不能做什么？
3. 方法与实现
   - 我选了什么方案？为什么不是别的？
   - 关键配置与参数（脱敏后）
4. 评估
   - 指标、方法、数据
   - 至少一张图、一张表
5. 局限与失败
   - 哪些没做到？哪些是运气？
6. 结论与后续
```

**第 5 节最重要**。一份不敢写局限的报告，说明作者还没真正懂。

### 2. 压测：证明它不只是「今天能用」

| 维度 | 做法 | 看什么 |
|:--|:--|:--|
| 时间 | 连续 24–72 小时 | 有没有周期性劣化 |
| 并发 | 多设备同时使用 | 带宽分配、连接数上限 |
| 负载 | 大文件上下行 | 吞吐上限、CPU 占用 |
| 故障 | 手动 kill 进程、断网重连 | 自愈能力 |

### 3. 方法论迁移：这套东西还能用在哪

你在这 16 周学到的，其实是一套**通用的「检测-对抗」分析框架**：

```
① 明确对手在看什么（威胁模型）
② 观测自己的行为（抓包/日志/指纹）
③ 找出与「正常」的差异（统计对比）
④ 用最小代价消除差异（权衡）
⑤ 量化验证（指标与图表）
```

这套框架可以直接迁移到：

| 场景 | 「正常」是什么 | 「差异」在哪 |
|:--|:--|:--|
| 反爬虫 | 真实用户的浏览节奏 | 请求频率、UA、指纹、行为序列 |
| WAF 绕过检测 | 正常 HTTP 请求 | 参数编码、请求头、时序 |
| IDS/IPS 规避 | 正常协议流量 | 分片、编码、协议合规性 |
| 风控对抗 | 真实用户 | 设备指纹、行为路径 |

> ⚠️ 注意方向：**同样的技术，用来「理解防御」是学习，用来「攻击他人系统」是违法。** 这套框架的价值在于让你能**设计更好的防御**，以及**评估自己的系统有多脆弱**。

### 4. 能力清单：给自己打分

回到 [ROADMAP](../ROADMAP.md) 的五个阶段门，逐条自评：

- ✅ 能讲清 / 能复现 / 能排错 → 3 分
- 🟡 能讲清但没实操 → 2 分
- ❌ 讲不清 → 1 分

低于 2 分的项，就是你的「回补清单」。**这比完成率更有价值。**

## 实验：24 小时压测脚本思路

```python
# 每小时做一次：
#   1. curl 一个固定小文件，记录 TTFB 与是否成功
#   2. ping 20 个包，记录 p50 / 丢包
#   3. 追加一行到 CSV
# 用 nohup / 计划任务跑 24 小时
```

产出一张「时间 vs 成功率/延迟」的折线图。**你大概率会看到晚高峰的凹陷**——这就是这条线路的真实性格。
