# 法律、条款与边界

> 这份文档不是法律意见，但它列出的边界是这个仓库自己遵守的，也建议你遵守。

## 1. 这个仓库的定位

它是一个**学习资料**，教的是：

- 网络协议怎么工作（这是公开知识）
- 审查系统怎么检测（这是公开研究）
- 抗审查协议怎么设计（这是公开论文与开源代码）

它**不提供**任何可用的服务器、订阅、账号或配置文件。

## 2. 法律：不同地方差别很大

| 地区 | 大致情况 |
|:--|:--|
| 中国大陆 | 自建/使用未经批准的跨境信道存在法律风险，《计算机信息网络国际联网管理暂行规定》等有相关规定，实践中对个人使用的处理尺度不一 |
| 香港 / 台湾 | 一般无特别限制 |
| 美国 / 欧盟 | 通常合法；但用于违法目的（欺诈、侵权）会另案处理 |
| 伊朗 / 俄罗斯 / 朝鲜等 | 有明确的限制或禁止性规定 |

**结论**：这不是一个「技术上能做所以就能做」的问题。**你自己要判断所在地的法律风险**，并承担后果。

## 3. 服务条款：这是另一回事

即使技术上连得通，**用代理访问按条款不对你开放的服务，通常违反该服务的 ToS**。

- OpenAI：有「支持的国家和地区」列表，从非支持地区访问违反使用条款
- Anthropic：同样有地区限制

后果可能是：**账号被限制或封禁**，且通常无法申诉。

这不是危言耸听，也不是道德说教——**这是你需要提前知道的成本**。W12 会让你亲自把这些条款读一遍。

## 4. 公开仓库的卫生

这个仓库是 **public** 的。以下东西**永远不要提交**：

| 绝对不要提交 | 为什么 |
|:--|:--|
| 服务器 IP / 域名 | 等于把机器交出去 |
| UUID / 密码 / shortId | 等于把钥匙交出去 |
| 私钥（`privateKey`、SSH key） | 同上，且无法撤回 |
| 订阅链接 | 通常是凭证 |
| 带个人信息的抓包 | 可能含 Cookie、Token |

`.gitignore` 已经忽略了 `private/`、`*.key`、`secrets.json`、`*.pcap`。**把你的真实配置放在 `private/` 目录里。**

> 记住：**Git 的历史是永久的**。即使你后来删掉文件，它仍然在历史记录里。清理历史需要 `git filter-repo` 重写全部提交，非常麻烦。
>
> 如果不小心提交了密钥：**立刻去服务器上换掉那个密钥**，这比清理历史重要得多。

## 5. 我不写进这个仓库的东西

以下内容**不会**出现在这里，也不建议你自己去做：

| ❌ 不做 | 原因 |
|:--|:--|
| 批量注册账号、养号 | 违反平台条款，且涉及身份欺诈 |
| 绕过封禁 / 申诉规避 | 同上 |
| 规避雇主/学校的安全监控 | 通常违反雇佣合同或校规，且伤害第三方（雇主）的正当安全利益 |
| 对他人服务器做扫描/探测 | 可能构成非法侵入；本仓库所有探测**只针对你自己的机器** |
| 提供现成可用的翻墙服务 | 涉及经营资质与法律责任 |
| 破解付费服务 | 侵权 |

**分界线**很简单：**你的行为有没有伤害到具体的第三方？**

- 学协议原理、搭自己的服务器 → 没有
- 扫别人的端口、绕过公司的审计 → 有

## 6. 做实验时的三条纪律

1. **只打自己的机器**。W14 的探测脚本，目标写 `127.0.0.1` 或你自己的 VPS。
2. **不要在真实生产环境做破坏性实验**。W04 的防火墙实验，封的是 8080 而不是 443。
3. **抓包文件别外传**。里面有你的浏览记录。

## 7. 如果这条路线让你不舒服

那也很正常。这套知识有一个更「干净」的用法：**把它当成防御视角的学习**。

学完你会发现，你能回答这些问题：

- 我们公司的网络监控能看到什么、看不到什么？
- 我们的服务怎么识别爬虫和异常流量？
- 我们的 TLS 配置有没有暴露指纹？
- 我们为什么会被 DDoS，怎么缓解？

**同一套知识，用来建比用来破更有价值。**
